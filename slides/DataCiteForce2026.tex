\begin{frame}{The DOI Minter: A Deliberate Architecture}
\begin{itemize}
    \item Native DSpace DataCite integration was too limited for
          enriched metadata (ORCID iDs, affiliations, relationships)
    \item Solution: a \textbf{custom DOI Minter service} connected
          to DSpace via REST API — separate from the platform
    \item Benefits:
    \begin{itemize}
        \item On-demand DOI registration for any item or subset
        \item   Full control over metadata sent to DataCite
        \item ``No risk'' to future DSpace upgrades or migrations
        \item Room to extend the service independently
    \end{itemize}
\end{itemize}
\vspace{0.5em}
Building a standalone service, rather than relying on native DSpace integration, 
made it possible to layer ORCID, ROR, and relationship metadata on top.
\end{frame}

\begin{frame}{Making People Visible — ORCID iDs}
\begin{itemize}
    \item KAUST became an \textbf{early adopter} of ORCID in 2015
    \item ORCID iD \textbf{required} for all thesis and dissertation
          submissions
    \item Integration works both ways:
    \begin{itemize}
        \item ORCID iD attached to the record in DataCite
        \item ETD metadata \textbf{pushed to the student's ORCID record},
              connecting it to their publication record as they start
              their careers
    \end{itemize}
    \item Faculty advisors and committee members also searchable
          by ORCID iD in the repository
    \item Datasets: ORCID proactively added for confirmed KAUST authors
\end{itemize}
\vspace{0.5em}
\textbf{Result:} 86\% theses/dissertations · 82\% datasets have ORCID iDs
\end{frame}

% -------------------------------------------------------------------
\begin{frame}{Making Institutions Visible — ROR}
\begin{itemize}
    \item 2018 — began adding \textbf{text affiliation} for KAUST authors
    \item 2022 — upgraded to include \textbf{KAUST's ROR ID}
          in affiliation entries
    \item Scope: KAUST-affiliated authors only
    \begin{itemize}
        \item DSpace submission forms do not easily support linking
              authors to affiliations for external co-authors
        \item Most DOI records are single-institution (KAUST)
    \end{itemize}
    \item Machine-readable affiliation makes KAUST outputs discoverable as an institution in DataCite Commons and beyond.
\end{itemize}
\end{frame}

% -------------------------------------------------------------------
\begin{frame}{Making Relationships Visible — Datasets and Articles}
\begin{itemize}
    \item Submitters can link a dataset or software record to a
          related journal article at deposit time
    \begin{itemize}
        \item Often only a title is available — the article has not
              yet been published
    \end{itemize}
    \item Library \textbf{manually follows up} periodically to add
          the DOI once the article is published
    \item Relation types and counts (as of 2023):
    \begin{itemize}
        \item 19 datasets + 2 software items with \texttt{IsSupplementTo}
        \item 5 theses/dissertations with \texttt{IsSupplementedBy}
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{The Unfinished Project — Reference Lists in ETDs}
\textbf{The insight:} a thesis cites hundreds of papers, but those
citations are invisible to the scholarly graph.
\vspace{0.5em}
\begin{itemize}
    \item Pilot (collaboration with Columbia University): collect
          BibTeX from graduates $\rightarrow$ convert to DataCite
          \texttt{relatedItems} with \texttt{References} relation type
    \item 200 authors contacted $\rightarrow$ 16 responses $\rightarrow$
          7 records enriched
\end{itemize}
\vspace{0.5em}
\textbf{What worked:} the DataCite infrastructure is ready — DataCite
Commons renders reference lists beautifully.\\[0.3em]
\textbf{What didn't:} asking authors to submit BibTeX files after
graduation — they have other priorities.
\end{frame}

\begin{frame}{A Direction Worth Exploring}
The pilot failed on author compliance --- not on infrastructure.
What if we removed the author step entirely?
\vspace{0.8em}
\begin{itemize}
    \item A separate project is converting KAUST thesis and
          dissertation PDFs to Markdown using
          \href{https://www.docling.ai/}{docling}
    \item This creates a \textbf{text layer already in place} for
          semantic search
    \item Reference lists are structured text — this pipeline
          \textit{could} be used to extract them automatically,
          without asking authors for anything
\end{itemize}
\vspace{0.8em}
This is a \textbf{direction to explore}, not a roadmap.
\end{frame}
